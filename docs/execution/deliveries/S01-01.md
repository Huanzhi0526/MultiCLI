## 实现结果

- 新增 `src-tauri/src/multicli/`，按冻结的 `domain.schema.json` / `error.schema.json` / `events.schema.json` 实现 Host、HostPath、AgentDefinition、AgentInstallation、Workspace、Session、SessionWorkspace、Run、ProcessIdentity/ProcessObservation、RunProcessLink、SessionRelation、Capability、Message、AppError、事件 envelope 与分页 DTO。camelCase 线名、枚举字面量、`additionalProperties: false` 均按 schema；领域对象带显式校验，非法输入返回 `invalid_argument`，不会静默落库。
- 建立独立 SQLite 领域库：固定文件名 `multicli.db`，只从显式传入的 MultiCLI 数据根打开；拒绝相对路径与 `.ccgui-next` 数据根。启用 WAL、`foreign_keys=ON`、5 秒 busy timeout；单写连接由互斥量保护。没有打开、迁移或改写上游 `app.db`，测试用合成旧库验证其字节不变。
- 版本化迁移：`schema_migrations` 版本表，v1 核心表与用户备注/标签，v2 消息访问索引；每个版本单独 `BEGIN IMMEDIATE` 事务。非空库升级前用 `VACUUM INTO` 生成一致备份并写 JSON manifest；失败回滚，保留旧版本与用户数据，不删库重建。数据库版本高于程序支持版本时直接拒绝，不写入。
- 内部服务层：工作区/Agent/会话列表、会话详情、能力读取、进程读取与 Run-Process 链接读取。列表统一 `limit`（1..200）/`cursor`/`total`；工作区筛选使用 `EXISTS`，跨工作区会话不会因关联行重复进入 page 或 `total`。排序稳定并带 id 次排序：会话 `createdAtMs DESC, id DESC`，工作区 `displayPath, id`，Agent `displayName, id`。
- 同一 Session 主记录同时支撑 Workspace 与 Agent 两个方向；详情中的消息、Run、工作区关联都来自同一 sessionId。`(sourceNamespace, nativeId)` 为原生唯一键，同来源同原生 id 幂等返回既有 Session，不同来源不合并；resume 通过新增 Run 复用 Session。
- 进程身份为 `hostId + pid + creationTime`；同 PID 新创建时间是独立观察，首次观察不被覆盖。Run 的 transport、ownership、executionStatus、interactionStatus、evidenceLevel 分列存储；external-observed 写入后不会被链接写入改写为 managed。

## 已知风险、接口变化与使用说明

- 新库固定为数据根下 `multicli.db`；数据根必须显式传入绝对路径，模块没有默认路径。`app.db`、`.ccgui-next`、真实历史均不会被该模块打开或迁移。
- Schema v1 建立核心表与用户自有 `user_session_notes` / `user_session_tags`；v2 增加消息排序/运行索引。表使用 SQLite `STRICT` 与 CHECK 约束，依赖项目已启用的 bundled SQLite（rusqlite 0.32），未新增依赖。
- 迁移备份位于 `<dataRoot>/backups/`，文件名含源版本、目标版本、毫秒时间与 UUID；manifest 为同名 `.json`。失败不会删库重建，错误 `details` 带 `stage/fromVersion/targetVersion/failedVersion/databaseVersion/backupPath`。
- 关键不变量（S01-02 及后续不得绕过）：`sessions(source_namespace, native_id)` 唯一（nativeId 非空时）；`workspaces(host_id, canonical_path)` 唯一（canonicalPath 非空时）；`processes(host_id, pid, creation_time)` 主键；`messages(session_id, source_key)` 唯一及同会话 nativeEventId 唯一；每个 Session 最多一个 primary 工作区；capability 按 `(agentId, name, installationId?)` 唯一。
- `ensure_session` 对相同原生身份返回已存在的 canonical Session；调用方应使用返回值的 id 再做关联，不要假定传入 id 一定被采用。首次进程观察不被后续同身份写入覆盖；链接首次写入不被后续冲突类型改写。若 S01-02 需要“确认所有权”升级，应新增显式操作，不能复用插入路径。
- 游标是不透明字符串，只对同一列表类型有效，未绑定过滤条件；跨过滤复用会从该排序位置继续，不会报错。会话默认按创建时间倒序、id 倒序；工作区按显示路径、Agent 按显示名。
- `SessionSummary` / `SessionDetail` 是本批内部读模型，S01-02 接 IPC 时可再映射为产品响应；冻结的领域实体字段不变。
