### 1.1 一个必须点明的判断

R2-05 的 `answered` 语义被拆成两件事：**"用户决定已提交"**（出站账本）与**"对端已应用"**（回执）。
产品界面显示的是后者；前者只作为审计记录。因此 queued 时既不显示"已完成"，也不关闭重试路径。

### 1.2 自验收追加：四个 P1 缺口（首版修复不成立的地方）

交卡前用独立审查代理做了对抗性复核，找出四处"主管反例过了、生产路径没修好"的缺口。已全部修掉并各带回归。
这一节单独列出来，因为它们说明**反例通过不等于生产生效**。

| 缺口 | 为什么首版不算修好 | 修复 | 回归 |
|---|---|---|---|
| 清扫器被 `pending` 门挡住 | `sweep_permissions` 只在还有 `pending` 请求时被调用，而"欠对端的 deny"只存在于**非 pending** 的槽位 → 到期/取消后的拒绝在**生产里一次都没发出**（主管反例直接调用 `run.sweep_permissions()`，绕过了这道门） | 新增 `has_pending_work()`：有 `pending` **或**有未履行的 obligation 都要跑；manager 改用它 | `an_owed_deny_keeps_the_sweeper_working_after_the_request_expires`（断言门谓词，不直接调 sweep） |
| 无 `turnId` 的协议在取消确认后仍可授权 | 归属门只看 `turn_id`；Claude/CodeBuddy 的权限请求恒为 `None`，取消被对端确认后 `cancel_pending` 又会清零 → 迟到的旧请求重新变成可答（R2-01 只修了"取消中"这一个窗口） | 新增 `accepting_permissions`：`send`/回合开始置真；`cancel`/回合结束/`stop` 置假；归属门把它作为第一判据 | `a_request_without_a_turn_id_is_void_after_a_confirmed_cancel` |
| "明确未发送可重试"在生产不可达 | 判据要求 `retryable=true`，但 `write_line` 的所有失败都是 `retryable=false`；stdin 已关闭明明是"一个字节都没写"，却返回 `Conflict` → 真实失败一律落到"结果未知"，重试分支是死代码 | stdin 已关闭改为 `Io + retryable(true)`（确实未写入）；写到一半失败仍保持不可重试（避免重复授权） | `a_write_that_never_reached_the_cli_is_reported_as_unsent` |
| `cancel` 的 2 秒轮询不是串行化 | 应答写线若超过 2 秒，`cancel` 会静默返回成功，之后 allow 仍然落线；且适配器缺失时预留的 `in_flight` 不回滚 → 该请求永久不可答、sweep 又跳过忙碌槽位 | ① 新增 `wire` 互斥锁：`answer` 跨协议写持有，`cancel` 必须先取得它才标记取消；拿不到就**返回错误**而不是假装成功。② 适配器缺失时回滚 `in_flight`/`answerable` | `cancel_waits_for_an_in_flight_answer_before_returning`（主管反例）+ 预留回滚；契约 §4.5 同步 |

另修两处同类问题：

- **`fail()` 先置 `terminal_persisted` 再提交**：提交失败时 stop 认为"已持久化"不再重试，Run 行永久停在 `starting`。改为提交成功后才置位，失败写备注，由 stop 重试。回归 `fail_does_not_claim_persistence_before_the_row_is_written`。
- **`CONTRACT_ERROR_PREFIX` 仍是文本推断**：工具输出（例如被读取的文件正文）以 `Tool permission request failed` 开头就会触发"契约错误"并封死整条会话。已整体删除该判据——协议错误由错误帧表达，工具输出只是数据。这正是 R2-07 禁止的推断方式，首版漏掉了它。

修正后主管全部反例、边界反例、ACP 反例与三款真实链**全部重跑**，结果见 §2、§3、§4。

## 8. 仍未做 / 风险

1. **CodeBuddy 真实正文 / 权限 / 工具 / 取消 / 继续**：ACP 连接未认证，全部 NOT_RUN；
   未调用 `authenticate`（会强制退出已有登录），未读取任何凭据。需要主管统一协调登录方式后再测。
2. **Codex 审批与 resume 各只有 1 次样本**：只能写"本次观测通过"，不能写"稳定"；
   端点不可达时会以同样方式表现为回合失败，报告已把前提写进契约。
3. **大输出截断、`updatedInput` 可改性**：仍为零样本，两个方向都不作断言。
4. **实窗完整运行与历史定位闭环**：本轮未做（任务卡列为仍需验收项）。
5. **CodeBuddy `queued` 后的恢复政策**：当前是"保持待答 + 提示可重试/取消"，没有自动重投；
   是否要自动重投需要产品决策，未擅自实现。
6. **`cancel` 现在可能返回错误**：若已有一次权限应答在写线上超过 35 s，`cancel` 不标记取消、返回可重试冲突，
   调用方必须把它当作"未取消"处理（这正是它要表达的语义，但 UI 需要相应提示）。
7. **无 `turnId` 协议的残余窗口**：取消后**立刻**开新回合时，旧回合的迟到请求与新回合的请求在协议上无法区分，
   当前按"新回合已开始即可授权"处理。要彻底消除需要引擎在权限请求里带回合标识；已在契约里注明。
