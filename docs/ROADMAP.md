# 后续维护方向

这些是0.1.0之后可讨论的方向，不是已批准或自动派发的任务。

| 方向 | 首先需要明确的问题 |
|---|---|
| 日常体验 | 用户在哪个页面、哪一步感到困难，期望怎样的行为 |
| 界面优化 | 信息密度、空态、入口、键盘操作和状态提示是否清楚 |
| 性能 | 具体数据规模和卡顿链路，建立可复现前后对照 |
| CLI版本维护 | 哪个产品/版本发生协议或格式变化，需要更新哪些能力声明 |
| Windows运维 | 新设备安装、升级、恢复和长期日志管理的真实问题 |
| 协作与构建 | 跨设备复现、CI耗时和开发环境说明是否足够 |
| 新功能 | 用户场景、数据/进程边界与现有架构是否适合 |

优先依据试用反馈决定。干净Windows环境安装检查和长时低内存样本是已知待补范围。
远程管理、SSH、崩溃终端保活、云同步与自动更新需要单独产品决策，不默认包含在维护工作中。
