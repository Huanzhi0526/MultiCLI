## 已复现并修复

1. xterm 尚未完成上一批解析时，连续通知可触发 21 次读取。修复后从 IPC 请求至解析回调均只允许一个在途读取；通知合流，轮询单计时器，卸载/晚到回调有代际保护。原独立反例未放宽，修后通过。
2. 终端输入并发写入缺乏顺序及排队上限。现按到达顺序串行写，排队加在途最多 1MiB，超限显示本地化错误。
3. 含空格/中文的 profile 会回退到共享 ProgramData/System Temp 写启动文件。现固定私有环境变量展开 cmd 文件路径，全部脚本留在自己 profile，路径探针覆盖中文、空格、`&`、百分号、括号。
4. 日志轮转失败后计数归零而继续追加旧文件，独立反例 1MiB 配置写到 1,638,402 字节。现错误可见并停止此日志，不越界。
5. Windows PowerShell 5.1 脚本向原生程序转发时丢空参数/引号并拆分 Unicode。ps1 链改为 PowerShell 7.3+ Standard 参数模式，真实 native helper 收到的 argv 与预期逐项相同；缺失/旧版明确失败，不安装依赖。
6. 成功托管会话未链接 cwd 工作区。现经现有规范化工作区服务建立 primary 链接；独立 SQL 反例从 0 条变为 1 条。
7. ProcessObservation 原先记录目标脚本而非实际 cmd/pwsh 镜像，现记录实际启动程序；脚本仍在终端视图中保留。
8. 已有非法字节会遮蔽块尾尚未完整的中文字符。现继续扫描非法区间并保留完整字符边界，独立反例由替换字符序列恢复为 `U+FFFD + 中`。
9. 日志轮转可拆开跨块 UTF-8/ANSI 序列。独立反例修前两个断言均失败；现完整边界轮转，未闭合尾部有 16KiB 上限，EOF 残片计入丢弃。
10. 当前文件和 `.1` 各用完整预算会导致合计两倍配置值。现各分一半预算，逐次写入检查两文件合计不超过配置值；初始每终端总日志预算仍 20MiB。
11. 正常退出时，内存终态可先于 Run 的数据库提交，应用退出会截断另一个线程的 finalizer。独立暂停回调反例修前失败；现 finalizer 串行完成，stop/应用退出等到持久化回调完成才返回。原测试与后续每轮真实数据库检查共同覆盖。
12. Windows 进程检查把 HRESULT 与裸 Win32 错误码比较，拒绝访问/已消失会误分为普通失败。现仅解码 FACILITY_WIN32，两个 API 共用映射；拒绝访问、已消失、普通失败有确定性回归。
13. 连续小块输出在 xterm 回调后立即再次 IPC 拉取，放大任务/分配负担。修前 5 秒 8 路共 5608 次 read；现所有通知与回调共享单调时钟的最早拉取时间，间隔至少 32ms，单次仍 64KiB，全部 pane 继续完整读取/解析。相同冒烟 1346 次 read、p95 61.4ms；微小输出连续通知反例修前 101 次/100ms，修后至多 4 次，通过原断言。不是跳过隐藏 pane、强制 GC 或排除慢样本。
