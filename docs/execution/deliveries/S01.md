## 已知风险、接口变化与使用说明

- 冻结领域 DTO 与 `docs/contracts/**` 未改。新增 `CapabilityQuery` 只是内部 IPC 查询形状；`Page<Capability>` 使用稳定 `(name, installationId)` 游标。
- 诊断文档是新格式，独立 `schemaVersion=1`；未来增加字段应先升版本并保持旧字段。
- `MultiCliStore::data_root()` 现返回去掉 Windows `\\?\` 前缀的路径；只影响展示/诊断，不影响唯一键或数据库位置。
- resolver 注册的 workspace id 为稳定哈希；历史合成 id 不会被重写。不同 Host 的相同路径永远不会合并。
- 启动失败的重试会刷新全部列表（工作区/Agent/会话）与已选详情，避免只恢复一个面板。错误文本可能包含本地数据库路径（仅界面），诊断文件不包含。
- `multicli_get_session` 按冻结 DTO 返回完整 messages/runs，未加分页上限；超长真实会话的内存/渲染边界 NOT_RUN，需 S02/S03 在契约层决定分页或上限。
- 畸形 IPC 参数在 Tauri 反序列化阶段被拒绝为字符串，而不是 handler 内的 `AppError`；前端 `toAppError` 会归一化为 `protocol` 错误，正常 UI 不受影响。若要连参数错误也严格冻结为 AppError，需要改命令签名为手动 `Value` 解析。
- 内部 `register_workspace` 仍允许 `canonicalPath = NULL` 的合成行（S01-01 既有测试依赖），可能重复；产品路径只走 resolver，resolver 拒绝未解析目录。若未来开放人工注册，需 S03 迁移增加 `(host, displayPath) WHERE canonicalPath IS NULL` 唯一约束。
- `multicli_shell_smoke` 保留为 S00 固定诊断命令（无参数、无任意命令入口），不是通用 shell 产品 API。
- 非法 `MULTICLI_PROFILE` 的错误 `retryable=false`，但 UI 的每个错误面板仍提供重试；重试会重新解析 profile/root，修正环境后无需重启。
- 本批未做 Git 写入；23 条待提交路径由 Sol 按授权提交。冻结清单对工作树字节负责，提交不会改变这些文件内容（除非随后再改代码）。
- fixture 工具只允许 test profile 或 temp/scratch 根；`--clean` 只删 fixture 派生行。**test profile 当前保留 fixture 数据**（3 agents / 2 workspaces / 3 sessions + `fixture-workspaces` 两个真实 worktree），便于 Sol 复现 A01/A20；清理命令：`cargo run --locked --example multicli_fixture -- --profile test --clean`（不会删非 fixture 行；`fixture-workspaces` 目录需手动删除）。`scratch/S01/backup-db` 是本轮 test 库备份，不是用户数据。
