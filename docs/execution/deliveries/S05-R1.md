### 3.4 本轮在真实链路上新发现并修掉的问题

真实链路不只是复核，它抓到一个单靠合成反例发现不了的缺陷：

**Codex 的 `turn/started` / `turn/completed` / `turn/start` ack 使用了常量 `sourceKey`**
（`codex/turn-started`、`codex/turn-completed`、`codex/turn-start-ack`）。同连接第二个回合的这三类事件
因此被去重判定为"重复投递"而整条丢弃：新回合拿不到原生 id，也无法按 id 关闭，界面会一直显示 running。
R1-05 修的是"重复事件不该改状态"，这条是反面——**合法的不同回合事件被误判为重复**。

修复：把回合 id 纳入去重键（`codex/turn-completed:{turnId}` 等）；`codex/cancel`、`claude/control-error`
这类"每次调用都该记一次"的事件改用 `local_key`（进程内唯一序号）。修复后复跑，两回合分别取得
`01a19fa7-…` 与 `01a19fa8-…` 两个原生 id，均正常 `completed`。

同时修正一处报告口径：原先把去重命中计入 `late_events`，导致真实回合里出现"已丢弃 17 个来自旧连接的
晚到事件"这种误导性备注。现在 `late_events`（旧连接）与 `duplicate_events`（重复投递）分开计数、分开展示。

## 4. 权限/取消并发与持久化收敛证据

- **应答与取消竞争**：`cancel` 先把该回合所有 `pending` 置 `cancelled` 再发中断，`answer` 只接受 `pending` 且未过期；
  `a_cancelled_permission_can_never_be_approved_afterwards` 与 `an_expired_request_is_refused_before_it_reaches_the_wire` 覆盖。
- **非法选项不消耗**：`answer` 先校验 `optionId` 属于该请求，再取走；`an_unknown_option_id_is_rejected_with_the_offered_list` 断言请求仍 `pending`。
- **旧事件隔离**：`events_from_a_previous_connection_never_reach_the_new_one`（generation）+ `an_old_turn_completion_cannot_close_the_new_turn`（turn 归属）。
- **DB 收敛**：`stop_waits_for_an_in_flight_terminal_commit` 用第二条连接 `BEGIN IMMEDIATE` 卡住提交，断言 `stop` 不提前返回、
  释放后能收敛；`a_process_exit_is_written_to_the_run_row_not_only_the_view` 断言进程退出写库。
- 真实链路两轮均核对 `SELECT id, execution_status, ended_at FROM runs`：全部 `exited` 且 `ended_at` 非空。
