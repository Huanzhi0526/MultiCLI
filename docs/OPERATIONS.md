# MultiCLI 运维说明

适用版本0.1.0。当前为Windows用户级未签名安装包，无应用自己的后台服务器或远程端口。

## 安装、更新与退出

安装目录默认%LOCALAPPDATA%/MultiCLI Workbench；数据独立在%LOCALAPPDATA%/MultiCLI/<profile>。
同产品新版本可覆盖安装，安装前建议在数据页备份；0.1.0只做过同代码版本夹具升级，不保证所有未来/历史迁移。
关闭主窗口只隐藏到托盘；使用页头“退出”或托盘“退出MultiCLI”才真正结束，自有活动运行可能要求确认停止。不要结束不属于工作台的外部CLI进程。

## 数据目录

| 内容 | 位置/性质 |
|---|---|
| 日常release数据 | %LOCALAPPDATA%/MultiCLI/prod |
| 开发/测试 | 同父目录dev、test；彼此独立 |
| SQLite | multicli.db、multicli.db-wal、multicli.db-shm；schema v7 |
| 备份 | 当前profile/backups；含已索引正文 |
| 诊断 | 当前profile/diagnostics；白名单计数、版本和能力摘要 |
| 终端日志 | 当前profile/logs；包含原始终端输出，可能有敏感信息 |
| WebView缓存 | 当前profile/webview |

MULTICLI_DATA_ROOT为当前进程可选绝对路径覆盖；排错先看“数据与备份”页实际目录，不要凭默认路径猜正在使用哪个库。
数据库采用WAL，只看主DB修改时间不能判断是否仍有新事务。不要使用上游portable-data.json或.ccgui-next作为MultiCLI数据。

## 备份与恢复

在“数据与备份”点“立即备份”，检查快照校验通过。快照含本应用已索引的会话与消息，不含CLI凭据、CLI原始历史或工作区文件。
恢复先写计划，在下次启动、打开DB之前执行；替换前保留pre-restore副本。清单、schema和完整性不符的备份不可用。
恢复期间失败需保留DB/WAL/SHM和错误信息，不能反复删除标记猜测修复。技术语义见[备份契约](contracts/profile-backup-v1.md)。

应用无法启动时：
1. 正常退出可关闭的自有应用，确认目标profile的DB没有仍被本应用使用。
2. 把当前DB、WAL、SHM及恢复标记一并复制到新的保留目录。
3. 核对目标快照的SHA256、清单schema和完整性。高于当前schema不能降级恢复。
4. 只对确认的当前profile替换数据库并处理旧sidecar；保留原文件，不在CLI历史目录中执行。
5. 重开失败则退出，用原DB/WAL/SHM恢复现场并保留诊断，再交维护者定位。

人工恢复绕过了应用自动保留步骤，必须先保留原件；不确定目录或库版本时停止替换。

## 常见排错

| 现象 | 先核对 |
|---|---|
| 首次会话空白 | 是否启用历史来源并完成刷新；首次无演示数据是正常行为 |
| CLI没被找到 | 安装页刷新，检查真实入口/PATH、扫描partial状态与未知候选 |
| 能打开CLI却无法结构化聊天 | 对照该版本入口、登录环境、协议与能力，不直接断言“没登录” |
| 用量为空 | 是否有官方机器出口、是否过期/退避；缺值不等于0 |
| 改动似乎没生效 | 确认运行二进制、源码commit、实际数据根与是否需要重建/重开 |
| 截图后显示器有黄框 | 检查本次自动化/截图工具的捕获会话并正常释放；不要关闭系统隐私提示 |

记录应用版本、CLI版本、操作步骤、实际结果与错误；优先用应用诊断摘要，不上传原始DB、终端日志和完整会话。

## 卸载与本地清理

正常卸载默认保留数据和备份；手动删除profile会删除其索引、备注和本地记录，先确认范围并备份。
target、dist、node_modules是可重建缓存；删除后后续构建成本增加，不影响已安装程序。项目本机用户当前选择保留这些缓存。
scratch中同时有工具链与私有证据，不能当作普通可一键删除的临时目录。references为固定只读参考。
任何大规模清理先列候选、范围与恢复方式，由用户决定；不要移动全局工具或用户CLI配置来做项目整理。
