## 2. U01–U09 / F01 / F02 逐条

### U01 超大文件不得声称完整（P1）

- 修前：`size > MAX_FILE_BYTES` 只 `files_skipped += 1` 然后 `continue`，`complete()` 不看它，
  于是"跳过了一个 32 MiB 的 usage 文件"仍输出完整窗口与累计值。
- 修后：`complete()` 要求 `files_skipped == 0`；跳过即整趟不完整，`window()`/`lifetime()` 返回 `None`，
  原因写进 `incomplete_reasons()`（"N 个转录文件超过 32 MiB 单文件上限，未计入"），
  再进快照 `unavailableFields`。上限保持 32 MiB / 64 MiB / 2000 文件不变。
- 回归：`transcript::an_oversized_file_makes_the_pass_incomplete_with_a_reason`；主管反例
  `supervisor_oversized_transcript_cannot_claim_complete_totals`。

### U02 深度剪枝不得声称完整（P1）

- 修前：`if depth > MAX_DEPTH { continue; }`，被剪掉的子树完全没有记录。
- 修后：在**决定是否下探**时计数：`depth + 1 > MAX_DEPTH` → `dirs_pruned += 1`；`complete()` 要求
  `dirs_pruned == 0`。原因："N 个目录超过 8 层深度上限，未继续遍历"。
- 回归：`a_pruned_directory_makes_the_pass_incomplete_with_a_reason`；
  `supervisor_depth_budget_cannot_claim_complete_totals`。

### U03 空 usage 对象不是四个已测 0（P1）

- 修前：`number()` 对缺失字段返回 `0`，`usage: {}` 被写成 4 个真实的 0。
- 修后：`TokenSums` 的四个分量都是 `Option<u64>`；`null` / 非整数 / 缺失 → `None`。
  合并规则是"两值皆知才相加，否则未知"，`total()` 要求四个分量全知才给总量。
  一整趟**完整**扫描里某窗口确实没有任何记录才是真实 0（`TokenSums::observed_zero`）。
- 回归：`an_empty_usage_object_is_unknown_not_four_measured_zeros`、
  `a_missing_component_makes_the_day_total_unknown_but_keeps_known_parts`、
  `a_real_reported_zero_is_kept_as_zero`、`an_empty_window_in_a_complete_scan_is_a_real_zero`；
  `supervisor_missing_usage_fields_are_unknown_not_zero`。

### U04 只采纳 assistant 实际用量（P2）

- 修前：只检查 `message.usage` 是不是对象，没有 type/role 判断。
- 修后：`type` 必须是 `assistant` 才计入；user / summary / system 记录一律跳过（返回 `records == 0`）。
- 回归：`a_user_record_is_never_counted_as_assistant_usage`；
  `supervisor_user_records_are_not_assistant_usage`。

### U05 截断的含 usage 行必须标记不完整（P1）

- 修前：`serde_json::from_slice` 失败直接 `continue`，行消失了但 `complete()` 仍是 true。
- 修后：解析失败计 `parse_failures`，`complete()` 为 false，原因写明"可能被截断"；
  窗口与累计值返回 `None`，不从剩下的有效行拼一个"完整"总数。
- 同组还保留并明确了其余预算：文件数 2000、总字节 64 MiB、单文件 32 MiB、深度 8、记录 400000，
  以及**20 秒墙钟预算**（`MAX_SCAN_MS`，超时即不完整并给原因，防止慢盘/网络盘卡住刷新线程）。
- 回归：`a_truncated_usage_line_makes_the_pass_incomplete`；
  `supervisor_invalid_usage_line_marks_scan_incomplete`。

### U06 Codex 总量不得伪装成 input（P2）

- 修前：`dailyUsageBuckets[].tokens` 与 `summary.lifetimeTokens` 同时写进 `inputTokens` 和
  `totalTokens`，伪造了 in/cached/out 明细。
- 修后：两者都用 `UsageSample::token_total`：`totalTokens` 保留真实总量，`inputTokens` /
  `cachedInputTokens` / `outputTokens` 为 `None`，`tokenSemantics` 为 `None`，
  note 写明"提供方只报告总量，未提供 in/cached/out 明细"。只有 `threadUsage.groups` 里官方真的
  给了明细时才展示 in/cached/out（`input-includes-cached`，总量 = input + output，不重复加 cached）。
  不同窗口（daily / lifetime / session）是不同样本，从不累加。
- 回归：`a_total_only_usage_read_never_invents_an_input_breakdown`、
  `cached_tokens_are_not_added_twice_for_codex`；
  `supervisor_codex_total_tokens_do_not_invent_input_breakdown`。

### U07 所有读取方法都失败 = error，不是空 partial（P1）

- 修前：`samples.is_empty()` 先命中，`(_, _, true) => Partial`，两个 RPC 全失败也报 partial。
- 修后：状态优先级 `unauthenticated → rate-limited → error（全部方法失败且无值）→ partial → ok`。
  `error` 的 `details` 带 `failedMethods` 摘要与 `methods[]` 结构化数组。
- 回归：`every_failed_read_is_an_error_not_an_empty_partial`；
  `supervisor_codex_all_methods_failed_is_failure_not_partial`。

### U08 429 + retryAfterMs 必须结构化保留并进入退避（P1）

- 修前：`failed_methods: Vec<String>` 只剩自由文本，`snapshot.retry_after_ms` 恒为 `None`；
  quota 429 与 token 成功同时发生时，token 成功把整个读取当成功并清退避。
- 修后：`MethodFailure { method, kind, message, rpcCode, retryAfterMs }`。`reading_to_snapshot`
  从 rate-limited 的方法取 `retry_after_ms`，状态保持 `rate-limited`（即使 token 成功），
  `error.details.methods` 保留每个方法的 kind/code/hint；`persist_snapshot` 据此写退避。
  统一入口保证：retryable → 写退避并 `attempts += 1`；measured → 清退避；
  其余（unauthenticated/unsupported/无值 partial）→ **中性**记录，既不设也不清退避。
- 回归：`a_quota_429_is_not_hidden_by_a_successful_token_read`、
  `a_transport_failure_keeps_what_was_read_before_it`、
  `a_quota_rate_limit_keeps_its_backoff_and_a_later_success_clears_it`；
  主管真实 stdio 对端反例 `supervisor_rate_limit_retry_hint_survives_real_stdio_reader`
  （fake 对端返回 429 + `retryAfterMs=120000`，快照保留 120000）。
- 顺带修：传输层失败（超时/管道关闭）不再让已读到的字段全部丢失，而是记一条 `transport` 方法失败、
  保留已读样本并标 `partial`。

### U09 带引号、目录含空格的转发器（P2）

- 修前：`expand_shim_variables` 之后按 `"` 切片再 `split_whitespace()`，`D:\native shim space\traex.exe`
  被拆成 `D:\native`、`shim`、`space\traex.exe`，解析失败。
- 修后：新增按引号分词的 `first_command_tokens`（cmd 双引号、PowerShell 单引号），空格不再拆路径；
  只认**命令位**：行首 `@` 去掉、`&`/`call` 前缀去掉后语句的第一个 token；必须以 `.exe`/`.com` 结尾、
  canonicalize 后仍在 shim 同目录、文件存在。`echo`/`Write-Output`/赋值/注释/标签/作为其他命令参数的
  路径都不是执行（因为它们的命令位不是 exe）。仍不执行 shim、不做脚本求值、64 KiB 上限不变。
- 回归：`a_quoted_cmd_forwarder_survives_a_directory_with_spaces`、
  `a_quoted_powershell_forwarder_survives_a_directory_with_spaces`、
  `printing_a_path_does_not_forward_to_that_executable`、
  `echo_assignment_comment_and_argument_positions_are_not_execution`、
  `a_target_outside_the_shim_directory_is_refused`；主管两条反例
  `supervisor_native_shim_keeps_quoted_paths_with_spaces`、
  `supervisor_native_shim_does_not_treat_printed_path_as_execution`（后者修复前是通过的，原样保留）。

### F01 打开着的页面跨过 expiresAt 必须转陈旧（P1）

- 修前：`freshness` 只在后端读取时算一次，页面一直开着仍显示"读数新鲜"绿色徽标。
- 修后：`freshnessNow(snapshot, now)` 用本地时钟重算，只降级不升级：后端 `stale`/`unknown` 保留；
  `now` 越过 `expiresAt` → `stale`；系统时钟回拨超过 1 分钟 → `unknown`。
  每 15 秒刷新一次 `clock`，卸载清定时器；过期时徽标转 amber 并显示「已过期」与「已过期，不代表当前状态」。
  纯本地重算，不启动 CLI、不发请求。
- 回归：前端 `expires a visible reading while the window stays open`；主管反例同场景。

### F02 普通刷新不得偷偷 force（P1）

- 修前：主按钮和错误重试都调 `refresh(true)`，绕过后端退避。
- 修后：主按钮与 `ErrorPanel` 重试都是 `refresh(false)`；另设一个**单独标注**的文字动作
  「强制刷新（忽略退避）」（`data-testid="usage-refresh-force"`，带说明 tooltip），只有它传 `true`。
  同时用请求序号丢弃迟到响应，避免旧结果覆盖新结果。
- 回归：`keeps the normal refresh on the backend backoff and forces only on demand`、
  `retries a failed refresh without forcing past the backoff`；主管反例断言点击主按钮时 `force === false`。
