# MultiCLI 0.1.0 界面与交互

## 会话导航与公共状态

当前入口为 `src/multicli/App.tsx`（`src/main.tsx` 直接挂载），替换 初始版本 的 `BaselineApp` 诊断脚手架。初始版本 的 `multicli_baseline_info`、`multicli_shell_smoke` 仍保留为开发诊断命令，但不再出现在产品页面。

页面是三栏只读导航：左栏在「工作区 / Agent」两个入口间切换，中栏是两入口共用的会话列表，右栏是共用的会话详情。同一会话从任一入口打开必须显示同一个 `sessionId`、同一组消息与 `messageCount` / `runCount`；筛选（工作区、Agent、来源）变化时清空选中会话并重置分页游标，已加载页按 id 去重、不重排。列表请求带递增 token，旧请求晚到不得覆盖新筛选的结果；组件卸载/切换时使 token 失效。列表分别呈现加载中、空、真实 `AppError`（code / message / retryable / details）与重试、以及「会话不存在」；失败不显示为空数组，空库不显示演示行。首屏失败显示错误与重试；「加载更多」失败保留已加载行，在列表底部或能力区给出重试入口。刷新时按钮禁用、列表显示加载态；刷新失败保留旧行并在上方显示错误，不把旧数据清空。

详情把 `origin`（managed / external-observed / history-only）、Run 的 `transport`（native / acp / pty）、`ownership`、`executionStatus`、`interactionStatus` 与 `evidenceLevel` 分开显示；能力 `status`（supported / unsupported / unverified）与证据层 `document` / `fixture` / `live` 用两组独立徽标，原因缺失写「未说明原因」，未确认字段写「未取得」，不把 unverified/fixture/NOT_RUN 画成 supported。原生 `nativeId`、`startedAt` 等缺失字段显示「未取得」，不留空白冒充已确认。

页头「导出诊断」按钮调用产品 IPC，成功显示真实本地文件路径与 `createdAt`，失败显示真实 `AppError` 并允许重试；文件只含白名单计数、版本与能力摘要，不含消息、提示词、命令、原生 id、账号、路径或凭据。导出目录由后端固定为 `<dataRoot>/diagnostics`，前端不能指定输出目录。`document.documentElement.dataset.appMounted = "1"` 的 boot watchdog 标记保留。

文案通过现有 i18next 机制及 `src/i18n/multicli.ts` 提供。未启用上游 App/bootstrap 的插件、遥测、远程和更新入口。测试数据只能由 `src-tauri/examples/multicli_fixture.rs` 显式写入 test profile 或 scratch 合成根，正式启动不生成演示数据。


## 安装与外部进程

顶部导航当前是九个视图页签：**会话 / 历史 / 安装 / 外部进程 / 终端 / 结构化运行 / 用量 / 自定义 CLI / 数据与备份**。会话页采用三栏只读导航（工作区 / Agent 两个入口打开同一会话），代码在 `src/multicli/SessionBrowser.tsx`，testid 与行为不变；空态给「去启用历史来源」按钮，不再提示用 fixture 工具造数据。

**扫描状态条**（两个发现页共用，`src/multicli/discovery/controls.tsx`）：显示 `status`（idle / scanning / ok / partial / error）、`generation`、`lastAttemptAt`、`lastSuccessAt`、采样/跟踪/不可读计数、扫描间隔下拉（3/5/10/30 秒）与「立即刷新」。任何失败都显示真实 `AppError`（`code` / `message` / `retryable` / `details`）与重试；整次失败时旧条目保留为 `stale`，不显示为空列表。固定说明写明「按间隔采样，短于间隔的进程可能漏见，不是审计级全量记录」，不允许删掉这句。

**安装页**每行显示产品、`agentId`、安装状态（`installed` / `unverified` / `missing-target` / `historical-residue`）、入口形态、入口路径、包入口与运行时、版本与版本来源、探测状态/时间/原因、`configProfileId` 与「配置 profile 未确认」徽标、发现来源与时间、最近扫描代次。版本只在探测成功时显示；探测失败保留原因并把版本留空，不能显示为「未安装」。

**外部进程页**每行显示 `state`（alive / exited / unknown）与 `freshness`（fresh / stale）两个独立徽标、产品与 `agentId`、PID、识别强度与证据、身份三元组（hostId · pid · creationTime，7 位小数）、来源程序与父进程、关联工作区（未关联时明写「未关联」）、脱敏命令、首次/最近发现时间。`identity` 为空时显示「未确认候选」，不显示伪造的创建时间。**没有**发送、接管、kill 或伪终端按钮，页脚常驻只读说明。

筛选（Agent / 状态）变化重置游标并重新读取第一页；分页仍按 id 去重、旧响应丢弃。外部进程页在无「加载更多」时按扫描间隔自动重读第一页；一旦用户加载了后续页就暂停自动刷新，避免游标跨扫描代次失效。跨代次游标由后端返回 `conflict`，前端显示错误并允许重读第一页。

设置只改本 profile 自有目录的扫描间隔（1–60 秒），不写任何 CLI 配置、注册表或系统代理。窗口真正退出时结束自有采样线程，不影响外部 CLI。

## 用量与自定义CLI

顶部新增两个视图页签：**用量**（`src/multicli/usage/UsageView.tsx`）与**自定义 CLI**
（`src/multicli/custom/CustomCliView.tsx`）。两者都是本机只读/本地配置入口，不联网写账号、
不注入斜杠命令。

**用量页**分三段：已确认账户（账户行 + 该账户的额度池列表）、未确认身份的额度池、各产品可读取
来源表。池卡片依次显示池标签、`agentId`、身份徽标（`身份已确认` / `身份未确认（不合并）`）、
「N 个安装共用此池」、读数状态徽标、新鲜度、采集时间、来源（`codex app-server …`）、失败原因与
退避提示、`本次未提供字段`、以及指标表（指标 / 已用-剩余 / 窗口 / 重置-明细 / 来源）。

- **未知、过期、未认证、不支持、限流、失败都不显示成 0**：没有数值时明写
  「本次没有数值：未知、过期或失败都不显示为 0」，不渲染空表格冒充成功。
- **失败读数与上次成功读数分开**：当前读数不是 `ok`/`partial` 时，把上一次成功的快照折叠在
  「上次成功读数（时间）」里，展开后才显示旧数字，标题始终带旧快照的时间。
- **费用估算与账单分开**：`cost-estimate` 必须有「估算」徽标，`billing` 显示「账单」，
  两者不合并成一个金额。
- **账户去重可见**：「N 个安装共用此池」直接来自后端池记录的安装列表长度；身份未确认的池
  永远列在单独一段，不与账户相加。
- 来源表每行显示产品、额度来源（machine / transcript / none）、token 来源、官方人工入口、
  状态徽标与限制；未安装的产品标 `未安装`，不显示为已支持。
- **安装状态是三态，不是「装了 / 没装」两态**：来源表的安装列显示 `已安装` / `已确认未安装` /
  `尚未确认`。`尚未确认` 只表示本次安装扫描没能覆盖全部根（无根、有不可读根或被截断），
  界面同时显示一行「本次安装扫描不完整」与「去『安装』页扫描」按钮；绝不把没看到写成未安装。
  物理安装优先于惰性登记：目录里真实存在的产品在用量页刷新时会被按需登记，不需要用户先打开安装页。
  本次刷新结果的每条原因用稳定的 `reasonCode` 本地化（zh/en/ko），后端原文只作为补充细节。
- **新鲜度跟着本地时钟走**：页面打开期间每 15 秒按 `capturedAt` / `expiresAt` 重算一次，
  越过过期点立刻转 amber 并显示「已过期」；系统时钟大幅回拨时记 `unknown`，不继续显示「读数新鲜」。
  这是纯本地重算，不会自动启动 CLI 或发起后台读取。读数的成功/失败切换只由真实刷新结果决定。
- **转录类读数不完整时不报数**：本地转录扫描只要漏读（超单文件上限、深度剪枝、含 usage 行解析失败、
  文件/目录不可读、扫描预算用尽），就显示「部分字段缺失」并列出原因，窗口与累计值显示为「—」，
  不从漏读子集拼出完整总量；缺失分量同样显示「—」，只有提供方真实报告的 `0` 才显示 `0`。

**自定义 CLI 页**上半是新增表单（显示名 / 可执行文件绝对路径 / 工作目录 / 产品提示 /
参数数组每行一个），下半是已保存条目。参数按行保存为数组，引号、空格、中文、`&` 原样保留，
**不解析 shell 语法**；保存失败显示真实 `AppError` 并保留输入。条目行显示入口路径、`argv`、
工作目录与「历史 / 额度：unsupported / unsupported」，删除只删配置，不停止已在运行的终端。

## 数据与备份

第九个视图页签 **数据与备份**（`data-testid="view-data"`，`src/multicli/data/DataView.tsx`）只处理
本应用自有 profile：显示 profile、数据目录、数据库文件、大小与 schema、日志模式、备份目录，并提供
「立即备份」、备份列表（文件 / 创建时间 / 大小 / schema / 校验 / 恢复）与计划恢复。

- **备份范围写在页面上，不靠用户猜**：页面用三语 `dataScopeNote` 明确「备份包含本应用数据库（含已
  索引的会话与消息内容）；不包含 CLI 凭据、CLI 原始历史文件或工作区文件」。页面不列 CLI 路径，
  不列账号指纹。后端 `scopeNote` 保留同一事实，供其他调用方核对。
- **恢复是两段式、跨重启的**：点「恢复」先弹确认框，确认后只写 `restore-pending.json` 并在页面顶部
  显示「待恢复」与取消按钮；真正替换发生在**下次启动、数据库打开之前**，当前库先复制到
  `backups/pre-restore-*`。本次运行中不替换任何打开着的数据库文件。若启动时应用失败，标记保留并置
  `failed=true`，页面显示「上次启动恢复失败，数据库未替换」，不再重复宣称「下次启动执行」。
- **校验不通过就不给恢复**：列表里的 `checksum-mismatch` / `missing` / `unreadable` / `invalid-name` 备份显示 amber/red
  徽标，恢复按钮禁用；来自更新 schema 的备份在计划阶段直接拒绝并提示不能降级恢复。
- **空态给下一步**：没有备份时写「还没有备份。点『立即备份』生成第一份。」，不显示假条目。
- 刷新入口：页头「刷新」重读 `multicli_profile_data`；备份成功后自动重读列表。见 [§7](#7-刷新入口清单)。

## 结构化运行

顶部新增第六个视图页签 **结构化运行**（`data-testid="view-runtime"`，`src/multicli/runtime/RuntimeView.tsx`）。
和终端页一样**保持挂载**（切页只隐藏不卸载）：结构化连接的生命周期不受视图切换影响，切回来必须还在同一个 Run 上。

**能力条（页面顶部，三列）**：每个已注册安装一行，显示产品名、版本、传输（`native` / `acp`），再把
`structuredChat` / `permissionFlow` / `toolEvents` / `cancel` / `resume` 五个字段各自用一个徽标显示
`supported` / `unsupported` / `unverified`。**不合并成一个总状态**：一款产品可以"能连、不能发消息"。
另起一行显示证据层（`live` / `document` / `fixture`）与原因文案。`live` 只表示"证据来自真实 CLI 观察"，
不等于"已验证"，因此同一行必须能同时出现 `live` + `unverified`。

**左栏**：新建运行表单（目标安装、绝对路径工作目录、首条消息）与运行列表。表单不做路径补全、不接受相对路径；
空安装时按钮禁用并写明原因。运行列表按开始时间稳定排序，选中项高亮。

**中栏**：运行头部（标题、产品与传输、执行态、交互态、取消本轮 / 结束运行、`run:{id} · session:{id} · native:{id} · pid`、
启动 argv 单行）＋ 会话流 ＋ 输入框。

中栏按剩余宽度收缩（`minmax(0,1fr)`），长会话 id/启动 argv 在栏内截断并保留悬浮全文，不得把右侧权限栏或结束运行按钮撑出窗口。应答等待在后台线程进行，界面仍能显示状态与取消/结束动作。

- 正文按消息气泡显示 `user` / `assistant`，未完成的标「流式接收中」；`message/completed` 到达后以权威全文替换，界面不叠加增量。
- 工具卡片显示名称、`kind`、**授权**（未请求授权 / 等待授权 / 已允许 / 本会话已允许 / 已拒绝 / 超时自动拒绝）、
  **执行**（执行中 / 已执行·成功 / 已执行·失败 / 已执行·结果未知 / 未执行），以及 `tool:` 与 `perm:` 两个**分开**的短 id。
  两个 id 不能拼成一个字符串：一次权限请求可能覆盖多个工具调用，反过来也成立。
- 只读工具（未触发权限询问）显示「未请求授权」，**不得**显示成「已拒绝」。
- 日志被淘汰时显示一行提示，正文以当前视图为准；不假装流是连续的。
- 输入框仅在「运行存活 + 无运行中回合 + 无待答复权限」时可发送，否则禁用并保持草稿。
- 可继续时显示「以同一会话新建运行」，点击后产生**新 Run**（`runId` 变、`nativeSessionId` 不变），不是在同一连接里重开。

**右栏**：待答复权限卡片（标题、详情、**请求实际给出的选项按钮**、状态、超时说明）、已处理请求、运行备注与错误。
选项按钮的 `optionId` 直接来自后端，前端不翻译、不添加、不猜测；没有「全部允许」这类产品自造选项。
`deny` 与 `deny+cancel` 是两个独立按钮（前者只拒绝这次调用、回合继续；后者中断整轮）。

**刷新模型**：`multicli://runtime` 只推 `{runId, seq}`；收到后按 runId 拉 `runtime_get`（80 ms 去抖），
外加 1.5 s 轮询兜底。**不把正文流塞进事件队列**，也不在前端按增量拼接字符串：视图就是重同步源。

**空态与失败**：无运行时说明如何新建；能力表失败显示真实 `AppError` 与原因；运行结束保留可读内容与结束时间。
所有 NOT_RUN / unverified 一律照实显示，不用假成功填充。

## 历史与搜索

顶部页签改为 **会话 / 历史 / 安装 / 外部进程**。历史页（`src/multicli/history/HistoryView.tsx`）是三栏只读索引：

**左栏：来源**（`SourcesPanel.tsx`）。每个来源显示产品、启用状态、索引状态徽标（idle / indexing / ok / partial / error / cancelled）、代次、文件计数（完成 / 总数 / 跳过 / 失败 / 未读完）、已索引消息数、最近尝试与最近成功时间、进度条、`configProfileId` 与「配置 profile 未确认」徽标，以及真实 `AppError` 与重试。没有正文、没有路径泄露到错误里。失败或部分失败时额外标「索引已过期」，不显示为「成功 0 条」。

`complete=false` 有三类原因，界面必须区分而不是统一说“已完成”：停在预算上（“本 pass 未走完”，下次继续）、有文件被拒绝（错误码 + 失败文件数）、有记录被隔离（`lineErrors` 与第一条的位置/原因，只有行号，没有正文）。`ok` 但仍有待复核文件时显示“完整性复核继续中”，不冒充全部校验完毕。操作：启用/停用、刷新、重建（**两段式确认**，确认按钮才真正清派生索引）、添加来源（候选下拉 + 手动绝对路径 + profile）。加入来源是本页唯一的写操作，且只写 MultiCLI 自有配置。

**中栏：搜索与浏览**（`SearchPanel.tsx`）。输入 300 ms 防抖；`≥3` 字符走 FTS5 trigram，`1–2` 字符走转义 LIKE 回退，界面用徽标显示本次 `matchMode` 并常驻固定说明。空输入显示「仅历史会话」浏览列表（`origin = history-only`）。命中行显示会话标题、Agent、kind、时间、同会话消息数与片段；片段是纯文本（不渲染 HTML），被截断时明写。搜索分别呈现：空输入提示、加载中、无结果、真实 `AppError` 与重试、「加载更多」失败保留已加载行并就地重试。筛选（Agent / 来源 / 工作区）变化重置游标。

**右栏：会话详情**（`SessionPanel.tsx`）。顶部是 `multicli_get_session_metadata` 的会话摘要（标题、history-only、Agent、原生 id、消息数、Run 数、首末时间、来源证据、消息类型计数、工作区与关联证据），**不内嵌消息**。消息由 `multicli_list_session_messages` 每页 50 条读取；点击搜索命中时带 `anchorMessageId`，命中的那条高亮并带「已定位到搜索命中」徽标，加载更多沿用同一游标。长消息折叠展开，工具输入放在独立折叠区，未知字段只列字段名。页脚没有「打开原文 / 执行命令」入口。

**三个入口同一套有界详情**：工作区、Agent 与搜索打开的同一个会话，走同一条
`get_session_metadata` + `list_session_messages` 链路（`src/multicli/SessionBrowser.tsx` 的
`useSessionDetail`），不再调用返回全部消息的 `multicli_get_session`。右侧详情显示
「历史会话 · 分页」徽标与「已加载 x/y 条」，`y` 取元数据里的 `messageCount`；还有下一页时
给「加载更多消息」，失败就地重试且保留已加载行。切换会话时旧请求的晚到响应被丢弃，
不会把上一个会话的消息画到新会话里。

游标会绑定关键字、过滤条件、会话与派生数据代次；条件变化或重建后旧游标返回
`invalid_argument`，界面显示真实错误并允许重查第一页，不静默返回短页。

**继续目标**只解析：检查按钮调用 `multicli_resolve_resume_target`，显示 resolved / blocked / unknown / unsupported 徽标、原因、冲突与证据。初始版本仅在resolved且executionAvailable时启用「继续为新运行」；用户明确点击后才走独立runtime_resume并转到结构化运行页。查看详情/搜索/检查均不启动CLI、不发模型请求；未知、冲突、缺安装时禁用，执行前后端再次检查。会话详情与历史详情共用此入口；恢复异步结果沿用运行页的选择保护。

固定文案：历史内容不可信，按纯文本渲染；搜索不依赖英文命中证明中文可用；索引受深度/文件数/字节/时间预算限制，预算用完时 `complete=false`，下次 pass 继续。

## 托管终端与生命周期

顶部九页导航包含终端；终端实现位于`src/multicli/terminal/`，只管理自有目标。

**工具条**（`TerminalWorkspace.tsx`）：「新建终端」只打开本机 shell 或已注册安装；`Ctrl+C（打断）`、`温和停止`、`强制终止`、`关闭标签` 四个动作**分开展示**，不合并成单个“停止”。没有终端时四个按钮全部禁用。右侧常驻上限说明（终端数 / 内存缓冲 / 日志）。

**标签**：每个标签显示状态点与状态徽标（starting / running / stopping / exited / failed）。切换标签不重建 PTY；隐藏的标签继续读取输出，因此切回时滚动内容仍在。关闭一个标签只停止它自己的进程树。

**终端面板**（`TerminalPane.tsx`）：xterm 首次挂载时才动态加载（`xtermLoader.ts`），WebGL 渲染器加载失败或被回收时自动退回默认渲染器。输入串行发送至 `multicli_terminal_write`，输出按 `multicli_terminal_read` 拉取：**上一批被 xterm 解析完成后才请求下一批**，所有唤醒共享至少 32ms 的合批间隔，慢渲染只在后端有界环中落后。隐藏 pane 继续读取/解析；尺寸由读循环检查实际布局盒，变化时 fit 并同步 cols/rows，隐藏零尺寸不提交退化几何。

**复制/粘贴**：`Ctrl+Shift+C` 复制选区（`Ctrl+C` 必须留给终端中断），右键有选区时直接复制，粘贴走浏览器原生 paste（多行保留）。复制失败显示真实提示，不静默。

**输入/日志边界**：输入按到达顺序串行发送，排队加在途最多 1MiB，超限显示本地化错误。日志在当前 profile 内写入，按完整 UTF-8/控制序列边界轮转；轮转/写入失败停止此日志并显示错误，丢弃有计数。当前文件与一个轮转文件各分配一半预算，合计不超过配置值。`.ps1` 启动需 PowerShell 7.3+；缺失或旧版明确报错，不自动安装。

**丢弃提示**：当后端因 4 MiB 上限丢弃历史时，顶部出现可关闭的固定提示「已丢弃 X（累计 Y）」，并注明新输出仍按字节顺序到达；`historyTruncated=false` 时不显示。

**状态栏**（`terminal-status*`）：显示状态、启动链、`runId`、进程身份（pid + 创建时间）、缓冲/丢弃字节、日志路径与轮转/丢弃计数、Job 约束（`kill-on-close` 或未约束原因）、退出码与信号、最近一次停止报告（模式 / 等待 ms / 是否升级）。**没有**把无输出解释成 idle：交互状态恒为 `unknown`。

**新建对话框**：目标下拉只列 `multicli_terminal_targets` 的真实条目，`missing` / `unsupported` 条目禁用并在下方写出原因；工作目录必填绝对路径；参数**每行一个**，按 argv 原样传递（不按空格拆分，空白行忽略，空字符串参数无法表达）；环境变量每行 `KEY=VALUE`，格式错误就地报错且不提交。创建失败显示真实 `AppError`（含 code 与 details），对话框保留以便修正。

**托盘与退出**：关闭主窗口只是隐藏到托盘，托管终端继续在后台排空。托盘「退出 MultiCLI」先发 `multicli://quit-requested`；前端用 `multicli_terminal_quit_check` 判断：没有自有终端直接退出，否则弹出「取消退出 / 停止自有终端并退出」两选一，绝不静默结束进程。外部 CLI 不在枚举范围内。



这些是当前已落地界面行为，后续优化以用户需求和实际实现更新，不沿用旧阶段任务或角色。
