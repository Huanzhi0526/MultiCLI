## 实现结果

### 1. 用户可观察到的行为

- 顶部新增「终端」页签（`view-terminal`）。新建对话框只列本机 shell（cmd / Windows PowerShell / 存在时的 pwsh）
  与数据库里已注册的安装；`missing` / `unsupported` / `unverified` 目标显示原因并禁止创建。
- 工作目录必填绝对路径；参数**每行一个**，按 argv 原样传递（不按空格拆分）；环境变量每行 `KEY=VALUE`，
  格式错误就地报错且不提交。创建成功后固定可执行文件、cwd、环境差量与启动链。
- 多标签：每个标签一个独立 PTY + Run + 进程树。切换标签不重建进程；隐藏标签继续读取输出。
- 工具条把 `Ctrl+C（打断）`、`温和停止`、`强制终止`、`关闭标签` 分开呈现，没有合并成单个“停止”。
- 状态栏显示状态、启动链、Run id、真实进程身份（pid + 创建时间）、缓冲/丢弃字节、日志路径与
  轮转/丢弃计数、Job 约束、退出码与信号、最近一次停止报告（模式/等待/是否升级）。
- 中断后终端仍为 `running`；温和停止超时会升级并明示；身份不一致时拒绝停止并给出原因。
- 历史输出被 4 MiB 上限丢弃时，顶部出现可关闭的「已丢弃 X（累计 Y）」提示；新输出继续按字节顺序到达。
- WebGL 不可用或上下文丢失时退回 canvas 渲染，终端仍可用。

### 2. 创建、启动链与参数保真

- 唯一启动/IPC 边界仍是 `src-tauri/src/multicli_bootstrap.rs`；领域代码在
  `src-tauri/src/multicli/terminal/`（model / ring / launch / identity / logfile / session / manager / tests）。
- 三条启动链（详见 `docs/contracts/terminal-v1.md` §2.1）：

  | chain | spawn 的进程 | 用户 argv 去向 |
  |---|---|---|
  | `exe` | 目标镜像 | `argv[]`，CreateProcess 按 MSVC 规则引用 |
  | `cmd` / `.bat` | `cmd.exe /d /s /c <trampoline.cmd>` | trampoline 内每条参数一个引号 token |
  | `.ps1` | `powershell.exe … -File <trampoline.ps1>` | trampoline 内每条参数一个单引号字面量 |

- trampoline 写在 `<dataRoot>/terminal/launch/<terminalId>/`，关闭终端时删除；命令行上只剩
  一个不含用户文本的路径。`.cmd` trampoline 前两行固定 ASCII（`@echo off` / `chcp 65001>nul`），
  之后才是 UTF-8 正文——这与 `cmd` 用控制台代码页读批处理文件的行为一致，已实测。
- 转义规则不是猜的：`%` → `%%`、`"` → `""`、结尾反斜杠段双写、引号内 `& | < > ^ ( ) !` 按字面，
  trampoline 以 `setlocal DisableDelayedExpansion` 开头（`!NAME!` 不会在 trampoline 这层被展开；
  目标脚本若自己开启延迟展开，那是它自己的行为）。这些规则先在真实 `cmd.exe` + 转发 `%*` 的
  shim + `node.exe`/`echo.exe` 上逐字符试出，再写成纯函数并加单测。
- **`.cmd`/`.bat` 目标只拒绝两种表示不了的参数**（`unsupported`，`details.stage=batchArgument`，
  在任何资源创建之前失败）：换行，以及 `"` 紧跟 `\`。原因见下一段的两次解析。
- **为什么引号从“拒绝”改成“支持”**：`.cmd` 目标通常是转发 `%*` 的 shim，参数要过两次解析
  （trampoline 一次、shim 一次）。旧的 `\"` 写法在 shim 那次解析里提前结束 token，实测会把
  `x"& echo PWNED` 变成两条命令；改成 `""` 后两次解析各切换两次引号、CRT 还原成一个 `"`，
  同一串在 `echo.exe` 与 `node.exe` 上都逐字节到达且不执行第二条命令。测试
  `the_cmd_chain_never_lets_an_argument_become_batch_syntax` 断言恶意串作为**单个** argv
  到达、且 `##ARGV##` 只出现一次；`the_cmd_chain_preserves_boundary_arguments` 与 `.exe`/`.ps1`
  共用同一份含引号的参数矩阵。`.exe` 与 `.ps1` 链本来就是按字面支持双引号。
- shell 目标不接受参数（若传入在创建前即被拒绝），它的 argv 是固定 launcher：
  `cmd /d /q /k chcp 65001>nul`、`powershell -NoLogo -NoProfile`。
- 目标身份在创建时固定：canonical 路径 + 文件长度 + mtime 形成指纹；只有 canonical 身份才视为
  “已核实”，仅显示路径的安装标 `unverified` 并拒绝启动。

### 3. 生命周期与所有权

```
open(spec)
  ├─ validate → 解析目标 → 取 terminalId/runId/sessionId
  ├─ ensure_session + start_run(status=starting)
  ├─ plan_launch（生成 trampoline）───失败→ run=failed + 返回 AppError
  ├─ openpty → spawn → pid
  ├─ Job Object（KILL_ON_JOB_CLOSE）──分配失败→ 结束子进程 + run=failed + unsupported
  ├─ 捕获身份(host+pid+creationTime)──失败→ 结束自有树 + run=failed
  ├─ 附加 reader/writer → 后台线程持续排空
  ├─ record_process + link_process(owned) → finish_run(running)
  └─ 失败任一步：不留下 running 的 Run，也不留下孤儿树

stop(interrupt)  → 写 0x03，状态保持 running
stop(gentle)     → 写 0x03 → 等 graceMs → 仍存活 → 复核身份 → TerminateJobObject → escalated=true
stop(force)      → 复核身份 → TerminateJobObject
close            → stop(默认 gentle) → 移出管理表 → 删除 trampoline
app exit         → shutdown_all(gentle, 2s) → app.exit(0) → RunEvent::Exit 再兜底 hard_shutdown_all
```

- `finalize` 幂等：reader EOF、显式 stop、重复 stop、迟到 kill 竞争时先到者胜出，后者被吸收。
- 退出检测有两条路：reader 的 EOF，以及每 150 ms 轮询自有子进程句柄的看门狗。ConPTY 在子进程
  结束后不一定立刻给 EOF，只看 EOF 会让已退出的终端一直显示 `running`；看门狗只读自己的句柄。
- Run 状态不可回退：`set_run_state` 拒绝对已 `exited`/`failed` 的 Run 写 `starting/running/stopping`，
  `open` 链接进程后也会先判断会话是否已经结束，避免“启动即退出”的目标留下 `running` + `ended_at`。
- 结束树之前复核 `host+pid+creationTime`；`Reused` 时**拒绝**并回到 running。
- Job 句柄随 Run 结束释放，内核清扫残留成员（包括 shell 留下的孙进程）；主进程崩溃同样由
  `KILL_ON_JOB_CLOSE` 清理，不实现崩溃保活。
- 外部进程完全不在枚举范围内：`close` / `shutdown_all` 只遍历 `sessions` 表。

### 4. 有界输出、日志与背压

- 每终端一个字节环（初始 4 MiB，可配 256 KiB–64 MiB）。前端用**绝对字节偏移**作为游标拉取，
  单次回复默认 64 KiB、上限 256 KiB。
- 环在裁剪时会推进到“解析状态为 Ground 且处于 UTF-8 起始字节”的位置；读取时若结尾是不完整
  多字节字符或未闭合控制序列，会留到下一次交付。因此跨块的中文/emoji/CSI 不会被拆开。
- 日志写 `<dataRoot>/logs/terminal/<terminalId>.log`（初始 20 MiB，可配），超限轮转为 `.log.1`；
  单块超过整个预算时整块计入 `logDroppedBytes`，不做半截截断。日志头部只记 argv 数量，不记参数值。
- 通知事件不含正文：每个终端最多一条未取走的 `output` 通知（读取即清 dirty），字节必须拉取，
  所以 WebView 变慢时落后量只在有界环里，并被 `droppedBytes` 计数与提示。
- 前端读取严格串行：上一批被 xterm 解析完（`term.write` 回调）才请求下一批。

### 5. IPC 与事件

`multicli_terminal_targets / open / list / read / write / resize / stop / close / shutdown_all /
limits / update_limits / quit_check` 与 `multicli_app_quit`，全部只在 `multicli_bootstrap.rs` 注册。
事件 `multicli://terminal`（`kind/terminalId/runId/streamId/seq/state/bufferedBytes/droppedBytes`）与
`multicli://quit-requested`。字段与错误码见 `docs/contracts/terminal-v1.md` §3–§4。

### 6. 托盘与退出

- 关闭主窗口只 `prevent_close()` + `hide()`，应用与托管终端继续运行、继续排空。
- 托盘菜单：`显示主窗口` / `退出 MultiCLI`；左键点击托盘图标恢复窗口（布局与滚动内容保留）。
- 托盘“退出”只发 `multicli://quit-requested`：前端先 `quit_check`，无自有终端则直接退出，
  否则弹「取消退出 / 停止自有终端并退出」，确认后才 `multicli_terminal_shutdown_all` + `app.exit(0)`。
- `RunEvent::Exit` 再调一次 `hard_shutdown_all` 兜底；任何路径都不会结束外部 CLI。

### 8. A11 三条启动链的真实参数矩阵

`src-tauri/src/multicli/terminal/tests.rs` 的
`the_{exe,cmd,ps1}_chain_preserves_boundary_arguments` 用同一个真实回显程序
（测试期用固定工具链编译的小 `.exe`，打印自身 argv 的 JSON）逐项比对：

| # | 参数 | exe | cmd | ps1 |
|---|---|---|---|---|
| 1 | `plain` | ✓ | ✓ | ✓ |
| 2 | `空格 分隔` | ✓ | ✓ | ✓ |
| 3 | `amp&ersand` | ✓ | ✓ | ✓ |
| 4 | `percent%50` | ✓ | ✓ | ✓ |
| 5 | `path%PATH%like` | ✓ | ✓ | ✓ |
| 6 | `paren(值)` | ✓ | ✓ | ✓ |
| 7 | `中文参数😀` | ✓ | ✓ | ✓ |
| 8 | `C:\目录 with space\`（结尾反斜杠） | ✓ | ✓ | ✓ |
| 9 | `caret^value` | ✓ | ✓ | ✓ |
| 10 | `pipe\|lt<gt>` | ✓ | ✓ | ✓ |
| 11 | `引号"内部"值` | ✓ | ✓ | ✓ |
| 12 | `x"& echo PWNED`（注入尝试） | 不适用 | ✓ 作为单个 argv，未执行第二条命令 | 不适用 |

第 11、12 项在 `.cmd` 链上能通过，是因为引号写成 `""` 而不是 `\"`。参数要过两次解析
（trampoline 一次、转发 `%*` 的 shim 一次）：`\"` 会在第二次解析提前结束 token，把值里的
`&` 变成第二条命令（旧实现实测复现，因此当时选择拒绝）；`""` 在两次解析里各切换两次引号
状态、最终由 CRT 还原成一个 `"`，同一串在 `echo.exe` 与 `node.exe` 上都逐字节到达。
第 12 项不是“字符串长得像”的断言：测试检查回显程序收到的 argv 恰好是两项、且 `##ARGV##`
只出现一次（若 `&` 生效，回显程序会被多跑一次或参数被拆开）。

三种链都仍然**只拒绝表示不了的输入**：`.cmd` 拒绝换行与 `"` 紧跟 `\`（创建前
`unsupported` + `details.stage=batchArgument`，不残留终端与 trampoline）；
`.ps1` 与 `.exe` 没有这条限制。

三条链都是**真实进程**：`.exe` 由 `CreateProcess` 直接启动；`.cmd` 经生成的 trampoline +
`cmd /d /s /c`；`.ps1` 经 trampoline + `-File`。断言是“回显程序收到的 argv 与输入逐项相等”，
不是“命令字符串长得像”。中文/空格工作目录在三个用例里都使用（`中文 目录`）。
`.exe` 与 `.cmd` 用同一个原生回显程序（`.cmd` 通过 `%*` 转发），`.ps1` 用脚本把 `$args`
序列化到文件——因为 `.ps1` 不是 CRT 进程，它的 `$args` 绑定才是要验证的对象。

- **崩溃清理**：应用被外部强制终止（工具宿主的 10 分钟上限杀掉进程）后，其终端子进程
  （pid 46884）在 1 秒内消失，命令行里带 `chcp 65001` 的 `cmd.exe` 计数为 0。这是
  `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 的实际清扫；同一时刻也有 ConPTY 句柄关闭，所以报告里
  把它写成“自有树没有存活”，不单独归因于某一行代码。

### 11. NOT_RUN 与已知限制

- **输入法组合过程**：只验证了“已提交文本”路径（CDP `Input.insertText` 等价于 IME 提交）。
  真实 IME 候选窗、组合中按键没有自动化，留待主管实机确认。
- **托盘图标点击/菜单项**：隐藏/恢复用 `user32` 验证了窗口层行为；“左键点托盘图标”“托盘菜单退出”
  本身没有 UI 自动化。退出流程用同一个 `quit_check → app_quit` 命令验证过。
- **三核心的登录与额度**：三个 CLI 只进入到各自的 TUI/登录前界面就关闭，没有发送提示词，
  因此没有模型响应、额度或费用数据；这是有意的（不消耗额度、不碰账号）。
- **psmux/持久化对照**：按任务卡只写设计取舍，未实现。
- **`.cmd` 参数的两个表示上限**：换行、以及 `"` 紧跟 `\`。两者都在创建前返回
  `unsupported`，不会静默改写。其余字符（含引号本身）已用真实 shim + `echo.exe`/`node.exe`
  逐项验证。
- **`.cmd` 依赖转发 `%*` 的 shim**：`""` 的还原发生在最终 CRT，因此目标 shim 必须把参数转发
  给原生程序（三核心的 `.cmd` 都属于这种）。若某个 `.cmd` 自己解析 `%1` 字符串而不是转发，
  它看到的是双写后的形式。
- **`.cmd` trampoline 目录**：要求“cmd 安全路径”（无空格、ASCII）。数据目录不满足时退到
  `%ProgramData%`、`%SystemRoot%\Temp`；都不可用则明确 `unsupported`，不静默降级。
- **`.cmd` 里的 `chcp 65001`**：依赖 cmd 逐行读取批处理并在切换代码页后按 UTF-8 解析后续行，
  本机 Windows 实测成立；若未来 cmd 改变该行为，需要改成 OEM 代码页写入 trampoline。
- **日志不含参数值**：只记参数个数与变量名，避免把 token 或提示词落到长期文件里。
- **上限修改只影响新终端**：已创建终端的环与日志已按当时预算分配（契约 §6 已说明）。
- **shell 目标的会话归属**：每个终端创建一个 `origin=managed` 的 Session，用内置 `local-shell`
  agent（vendor=`local`）。它因此会出现在会话列表里（0 条消息），这是“一个终端就是一个 Run”
  的直接后果，不是伪造的 CLI 产品。
- **单实例上限**：同时最多 16 个终端（常量），超出返回 `conflict`。
- **A20 的 `stale` 不适用于终端目标**：`stale` 是 S02 发现视图的概念（进程/安装过期）。终端页用
  `ready` / `missing` / `unsupported` / `unverified` 加 `reason` 表达“能不能启动”，运行期错误一律是
  真实 `AppError`（带 `code` / `stage`）。这里没有把 `stale` 硬塞进终端 DTO。

## 12. 独立复核后的修复（本会话内完成）

交卡前做了两轮独立复核（只读，一轮按任务卡逐条对照、一轮专查代码与注入面），发现的问题与处理：

| 复核发现 | 严重度 | 处理 |
|---|---|---|
| `.cmd` 参数里的 `"` 会提前结束批处理引号，后面的 `&` 可被当作命令执行（复核者用最小 `.cmd` 实测复现） | 阻断 | 先把 `"` 改成创建前拒绝；随后实测发现 `""` 双写在“trampoline + 转发 `%*` 的 shim”两次解析下可完整还原且不执行第二条命令，于是改为**支持引号**，只拒绝表示不了的换行与 `"\` 相邻；A11 表第 11/12 项据此更新 |
| 目标启动后立即退出时，`open` 的“链接→置 running”可能覆盖 reader 已写入的终态，留下 `running` + `ended_at` | 高 | `set_run_state` 加“终态不可回退”条件；`open` 链接后先判断会话是否已结束；新增 `a_target_that_exits_immediately_still_ends_its_run` |
| 只靠 reader 的 EOF 判断退出：ConPTY 不一定立刻给 EOF，自然退出的终端会一直显示 `running` | 高 | 增加每 150 ms 轮询自有子进程句柄的看门狗；实窗 `exit` 1 秒内变 `exited` |

| 切页/隐藏后 `ResizeObserver` 不再收敛，xterm 与 PTY 几何会分歧 | 中 | 改为读循环驱动的几何同步（只比较布局盒尺寸，隐藏时跳过），实窗 186→89 |
