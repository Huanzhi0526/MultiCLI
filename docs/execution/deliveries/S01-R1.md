## 已知风险、接口变化与使用说明

- 字段类型仍是 `Option<T>`，没有改变探针/调用方的构造方式；变化只在反序列化边界：required nullable 字段缺键现在是错误，显式 `null` 仍可。序列化保持 null/值。`required_nullable` 依赖 `deserialize_any`，适用于当前 JSON IPC/探针；若未来接入非自描述格式需复核。
- 数据根 `data_root()` 现在返回解析后的实际路径（`std::fs::canonicalize` 最长已存在祖先 + 未存在后缀）。调用方若比较原始别名路径，应使用返回的解析路径。普通 junction 可用；解析到 `.ccgui-next` 的别名在创建目录/数据库前拒绝。
- 安装登记现在要求 id 与自然身份 `(hostId, agentId, configProfileId)` 同时一致才幂等；同自然身份换新 id 会 `conflict`。S02 应优先查询/复用既有安装 id，不能依赖“回读任意既有行”。
- 归属错误码：Message/Run/Capability 归属不一致为 `invalid_argument`（details.field 明确）；external-observed 的 owned 链接为 `access_denied`；安装冲突为 `conflict`。拒绝前无写，事务回滚。
- 领域归属由 repo 的事务预检保证，不是仅靠单列外键；所有产品写入必须走 service/repo，不能绕过直接 SQL。未来若增加批量导入，应复用同一预检或增加等价 SQL 约束。
- 相邻但不在本次六组范围内的归属检查：安装可执行文件 `HostPath.hostId` 与 `AgentInstallation.hostId`、`SessionWorkspace` 两侧 host、`RunProcessLink` 进程 host 与 Run 所在 Session host 目前未额外强制；这些属于 S02/S03 发现与路径接入时应补的领域一致性项，本批未擅自扩大范围。
- 非空但没有 `schema_migrations` 表的未知库当前按 v0 处理（会先设 WAL 再尝试 v1）；R1-05 明确覆盖的是“较新版本、被拒绝前零写入”的 999 场景，该未知库场景未纳入本轮，S02 前应决定是否直接拒绝。
