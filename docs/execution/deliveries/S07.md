### 2.2 用量页安装状态文案

`presence` 三态（`installed | not-installed | undiscovered`）由**本次真实扫描**判定：

- 扫描覆盖全部根且没有入口 → `not-installed`（可写「已确认未安装」）；
- 有任何不可读根、零覆盖或截断 → `undiscovered`（只写「尚未确认」；对本身有可读表面的产品，
  `status` 降为 `unverified`，本身无可读表面的仍为 `unsupported`）；
- 找到可运行入口 → `installed`。

扫描摘要 `catalogScan` 一并返回，界面显示「本次安装扫描不完整」与「去『安装』页扫描」按钮。

**惰性登记修复**：刷新时若数据库无该产品安装行，但扫描发现真实安装，先按 S02 同一身份规则登记
（`install_id` / `identity` / `identityKind` 一致）再建池。旧行为会返回「未注册该产品的安装」，
即使物理安装存在。

**原因码**：`outcomes[].reasonCode` 为 `not-installed | not-discovered | backoff | no-usage-roots |
unsupported-source | no-number | read-failed | partial | unauthenticated | unknown`，zh/en/ko 均有
文案；后端 `reason` 保留原文作细节。英文 `stage` 过期文案一并修正为产品 tagline。

默认刷新仍 `force=false`、遵守退避；本地时钟过期只重算徽标，不启动 CLI（S06 行为未改）。

- 只导出本 profile 的 `multicli.db`；**快照包含本应用已索引的会话与消息内容**（用户要备份的正是这些），

- 恢复只写 `restore-pending.json`，**下次启动、数据库打开前**才替换；替换前复制当前库到
  `backups/pre-restore-*`；校验和/完整性/schema 任一不通过即拒绝。schema 以**快照自身的
  `schema_migrations`** 为准，清单无法把新库伪装成旧库；apply 阶段会再验一次，防止计划后替换文件
  或降级应用绕过。
- 替换时把旧 `-wal`/`-shm` **移动到** pre-restore 目录而不是删除；任何一步失败都把 sidecar 移回，
  已提交未 checkpoint 的事务不会因失败路径丢失。启动时应用失败会保留 marker 并置 `failed=true`，
  数据页明确显示“上次恢复失败、数据库未替换”，不再重复承诺“下次启动执行”。
- 迁移未改：v7，事务 + 迁移前 `VACUUM INTO`；迁移安全副本写入 `backups/migrations/`，不会在用户
  备份列表里显示成“无法读取”的假备份。失败回滚测试仍通过。
- 当前 test 库**未被还原/清空/seed**；验证使用只读复制出的隔离副本（§5.2）。

### 4.2 8 终端 × 100 KiB/s 持续 60 秒 + 20 轮

- 测量对象：**生产 `TerminalManager`**（ConPTY → 读线程 → 4 MiB 环形缓冲 → 64 KiB 读批次）；
  不含 React/xterm 绘制与 Tauri IPC 序列化，因此回显数字是窗口可见延迟的**下界**。
- 负载：8 个 `cmd.exe` 托管终端，每个用本地 Python 辅助程序持续输出（名义 100 KiB/s，实测
  **109.66 KiB/s/终端**，60 秒共 **53,901,262 字节**，高于名义值，不是减弱负载）。
- 回显：80 个样本（每 750 ms 一次，写 `echo` 后等回显），**p50 1.91 ms、p95 3.54 ms、max 4.04 ms**；
  目标 ≤ 200 ms → **PASS**。
- 串流：每终端只出现自己的标记，**无跨终端串流**（`foreignMarkers` 全为空）。
- 背压：本轮环形缓冲显式丢弃 **2,557,626 字节（约 4.7%）**，通过 `droppedBytes` 报告，不是静默丢失；
