# 性能维护与已有测量

以下是0.1.0在本机Windows11 x64、Ryzen7 7735H/16线程、约16GB内存上的观察结果，不是对所有设备的保证，也不是后续任务的固定验收矩阵。

| 对象 | 已有结果 | 测量范围 |
|---|---|---|
| 外部发现 | 20样本p95 3076.20ms，max5194.71ms | 416桌面进程、20个自有Codex空连接、3秒扫描；后台到DTO，不含React绘制 |
| 历史列表/搜索 | 最慢暖缓存p95 623.752ms | 10k合成会话/100k消息、生产SQL与映射；不含IPC/React |
| 安装版空闲 | 302.26秒，整机平均CPU0.124%，峰值工作集458.21MiB | 应用与所有自有WebView/辅助子进程，无CLI/导入，无监听 |
| 八终端回显 | 80样本p95 42.60ms，max46.70ms，最大帧间隔16.70ms | 每终端100KiB/s持续60.07秒，实际IPC/ConPTY/xterm与两次动画帧 |
| 终端释放 | 20轮后活动终端0、孤儿夹具0；句柄首5轮max429、末5轮min424 | 同速率、每轮就绪后3.5秒负载并有1.5秒预热；不是每轮60秒 |

终端前端测量使用从产品基线归档建立的私有入口和观察钩子，保留生产TerminalPane与IPC路径；它不是交付二进制，也不是物理键盘到像素的光学计时。
原始私有探针位于本机scratch，不属于远程开发者必须拥有的工具。新优化应建立可复现、无真实内容的夹具并写明口径。

## 后续定位建议

- 先固定源码、数据规模、设备、后台负载和采样方法，再比较前后变化。
- 分开测源到达、解析、数据库、IPC、React更新、xterm写入与帧提交，不拿局部耗时当全链结果。
- 对照长消息/中文/emoji、页面切换、多个终端、后台与恢复；记录内存、句柄、订阅、定时器和自有子进程是否收敛。
- 优化必须保留正文、顺序、权限与Run归属。无界队列、隐藏错误、丢字和增加不透明延迟都不能当成提速。
- 对长时运行、低内存设备或真实大历史，当前尚无充分样本；需要时补测，不外推承诺。
