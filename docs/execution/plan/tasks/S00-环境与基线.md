# S00 环境、参考仓库、底座与远端

执行：Sol。起始 NOT_RUN。前置：用户启用施工；计划讨论不触发。本阶段允许脚手架和最小探针，不展开全部业务开发。

## 工作

1. 检查根目录、现有 Git、用户改动及规则。使用 `plan/02-参考项目.md` 的 app/references/scratch 布局，已有仓库则适配而不是覆盖。
2. 记录 Windows 版本/架构、Git、PowerShell、Node、pnpm、Rust/MSVC、Windows SDK、WebView2。对照选定上游清单安装缺失前置；不为本项目修改 Hyper-V、WinNAT、系统安全策略。
3. 下载必需参考快照，记录真实 commit、许可证、阅读路径。参考项目只用于读，不批量安装所有参考应用。
4. 选择 Desktop CC GUI 一个可复现的 commit/tag，保存 lockfile；跑依赖恢复、前端构建、Rust 检查、桌面启动与安装包构建。失败日志要能区分环境问题和上游问题。
5. 最小探针：中文/空格工作目录中启动 shell PTY、输入/resize/退出；查询 Codex 协议能力、CodeBuddy ACP 握手及 Claude 当前非交互能力，不发送付费推理作版本探测。
6. 读真实引擎/会话/数据库/终端模块，生成 `SOURCE-MAP.md`：领域服务对应到实际路径。冻结 Schema、Run 生命周期、能力字段、错误类型和事件格式，供 S01 使用。
7. 切换 MultiCLI 的 app identifier、显示名、数据根和更新源；dev/test/prod 分目录。上游远程访问、relay、遥测、computer-use、插件安装与自动更新默认关闭，核对后台入口而非只藏菜单。
8. 清点本机核心 CLI 与 TRAE 实际产品：可执行路径、版本、安装来源、可读历史根；只记录脱敏摘要。缺失的登录由用户自行完成，不读取 token。
9. 建立本地正式 Git、.gitignore、第三方说明、CI 和统一验证入口。复制方案进入正式 repo 的 docs/execution/plan，原 plan 保留。既有 AGENTS.md 合并必要项目条款，不覆盖原规则。
10. 检查 GitHub 可用目标。没有目标时本地准备结束后询问 owner/repo/可见性；关联 origin/upstream，首个基线提交和推送由 Sol 做。

## 底座选择门

默认派生底座必须满足：Windows 桌面和测试安装包可构建；PTY 最小链路可用；三核心引擎有可隔离入口；能独立数据目录；能关闭超范围后台能力。保留可用上游功能，不用“全新设计更干净”作为重写理由。

先安排一个有上限的基线验证批次（建议 4–8 小时有效工作），最多两轮针对性修复。若仍有阻断或需要改造大量无关子系统，Sol 写 ADR-001：具体失败证据、可移植模块、切换成本，按本方案退路建同栈最小骨架。时间预算是停止无效探索的建议，不允许通过缩减验收造出假通过。

退路不得改变 R01–R09，只调整源文件结构与批次估算。S00 不通过不得派 S01。

## 验收

A18；普通权限启动；真实 shell PTY；独立数据目录；锁定依赖恢复；安装包可启动；文档来源准确。认证探针未运行、参考仅下载未读、远端未推送都应分别报告，不能混成“环境完成”。如果缺登录，S00 可以完成基础环境，但 S05 真实核心验收条件必须列为后续阻断，不能遗忘。
