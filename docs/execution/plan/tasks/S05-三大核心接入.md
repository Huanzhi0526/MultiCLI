# S05 Codex / Claude Code / CodeBuddy

前置 S04 ACCEPTED。每款独立子批次，不能一次派出三份并行写入。

## 子批次

1. S05-01：统一事件流、权限请求、错误/取消状态机、协议契约测试；保留 PTY 模式选择。
2. S05-02：Codex app-server，按锁定 CLI schema 接线程、turn、权限、事件、继续与取消。
3. S05-03：Claude 官方受支持结构化 CLI/SDK 路线，复核上游接入，完成权限往返与历史关联。
4. S05-04：CodeBuddy ACP，initialize 能力协商、session/new/prompt、权限、取消、load/resume 按声明调用。
5. S05-05：三款统一 UI、并发与恢复冲突测试。

## 实现要求

- CLI 复用已有官方认证，不提取凭据到新数据库；支持自定义 executable/profile 路径。
- UI 不把三款特有字段压成一个过于简单字符串；工具调用 id、流式增量和结束原因保留。
- IPC/协议断开时旧请求失效；重复事件幂等，超时后没有永远 spinning。
- native_id → Session → 新 Run 的关系稳定。load 展示历史与 resume 执行行为区别明确。
- 无支持声明的 ACP 方法不能试探性调用到成功为止。扩展字段在 adapter 内隔离，不侵入全局 UI。
- 不以 `--dangerously-skip-permissions` 绕过权限流程来交付“可运行”；施工宿主权限与产品默认权限分离。
- 对话开始只由用户动作触发，索引/详情页打开不发送模型请求。
- 外部活跃会话不能被自动重启、结束或迁移；仅提供可验证的继续流程。

## 验收

A12/A13/A14/A20；Sol 在隔离临时项目内对三款各执行真实链路：新建 → 文本 → 请求一次文件操作 → 拒绝并证明未执行 → 允许另一次操作 → 显示工具结果 → 完成 → 退出 → 历史定位 → 继续 → 取消。

分别覆盖未登录、未知 CLI 版本、协议断开、权限到达后取消、多个并发请求、同会话继续冲突。真实推理需要用户已有可用账号；缺失时该款 NOT_RUN，先完成其他子批次，不伪装通过。

上游代码不能通过简单改产品标签就当第三款接入；须核对三款各自命令、返回字段与历史一致性。

## 回交

三款版本矩阵、协议记录（去敏）、权限/取消测试、真实历史继续证据、适配来源、未支持项与 PTY fallback 行为。
